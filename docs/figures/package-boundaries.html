Architecture · nakama-go-server-kit

Four packages that do not know what Nakama is

The kit is the part of a game server that is testable on its own: no import of the game server runtime anywhere, so every test is a plain go test -race with no server to start and no container to wait for.

measured: 55 tests · 95.1% coverage · go test -race in ~1s · go.mod has no require line
Two decisions worth the shape of a picture

storage.Once keeps its id ledger inside the same object as the state, because a check and its effect have to be one compare-and-swap. Checking ids in one table and granting in another is a race that passes every test until two requests arrive together.

An error returned by change in storage.Update is not retried: “not enough gold” is a decision, not a conflict — retrying it charges the player twice or not at all.

Everything above is one claim: the runtime is a dependency of the server, not of the logic. The numbers are from the repository's own test run; the two notes are the two places where the code is doing something a reader would otherwise assume was a bug.
